这篇笔记将之前分散的博客搭建步骤整理到一起，记录使用阿里云轻量应用服务器、宝塔面板和Hexo部署博客的流程。

文章中的域名用`xxxx.top`代替，请替换成自己的域名

## 1. 部署思路

Hexo负责在本地把Markdown文章生成静态页面，服务器只需要通过Nginx提供这些文件，不需要安装Node.js或运行Hexo。

整个流程如下：

```text
本地图片
    ↓ PicList压缩、上传
图床（MinIO或OSS/COS）
    ↓ 获得图片HTTPS链接
本地Markdown引用图片链接 + 主题配置
    ↓ hexo generate
public目录中的静态页面（保留图片链接）
    ↓ hexo-deployer-git通过SSH推送
服务器Git裸仓库 /var/repo/hexo.git
    ↓ post-receive钩子检出文件
网站目录 /var/hexo
    ↓ Nginx返回HTML、CSS、JS
浏览器显示博客
    ↓ 根据页面中的图片链接发起独立HTTPS请求
图床返回图片，浏览器加载文章配图
```

图床保存图片文件，Hexo文章保存图片链接。使用外链的图片不会因为生成博客而被复制到`public`目录；读者打开文章时，由浏览器直接向图床请求图片。

随机封面也使用图床中的图片，只是在访问图片前多经过一次随机API：

```text
浏览器请求 random.xxxx.top
    ↓ PHP从img.txt中随机选取一个图片链接
API返回302重定向
    ↓ 浏览器访问重定向后的图片地址
图床返回随机封面图片
```

博客源码仓库和部署仓库是两个不同的仓库。GitHub保存文章、主题和配置；服务器部署仓库接收生成后的HTML、CSS、JS等文件。

工具链如下：

- 阿里云轻量应用服务器，系统使用Ubuntu
- 宝塔面板与Nginx
- 本地Node.js、Git和Hexo
- Git裸仓库与SSH密钥
- 域名与SSL证书
- Bufferfly主题
- MinIO
- PicList

## 2. 准备服务器和域名

### 2.1 服务器与防火墙

创建轻量应用服务器后，记录公网IP，通过控制台远程连接或SSH登录。

在服务器的防火墙中确认放行以下TCP端口；如果系统另外启用了UFW等防火墙，也需要检查对应规则。

| 端口 | 用途 |
| --- | --- |
| 22 | SSH登录与Git推送，修改过SSH端口则使用实际端口 |
| 80 | HTTP访问 |
| 443 | HTTPS访问 |
| 宝塔实际面板端口 | 管理面板，按安装结果填写，建议限制管理来源IP |

轻量服务器的端口规则可以在控制台管理，操作参考[阿里云网络安全说明](https://www.alibabacloud.com/help/en/simple-application-server/network-security01)。

### 2.2 域名解析

在域名实际使用的DNS服务商控制台中，找到`xxxx.top`的解析设置，手动添加以下记录。在宝塔中创建站点或绑定子域名，不会自动完成DNS解析。

| 主机记录 | 类型 | 记录值 | 用途 |
| --- | --- | --- | --- |
| @ | A | 博客服务器公网IPv4地址 | 访问`xxxx.top` |
| www | A | 博客服务器公网IPv4地址 | 访问`www.xxxx.top` |
| img | A | 图床服务器公网IPv4地址 | 访问`img.xxxx.top` |
| random | A | 随机图片API服务器公网IPv4地址 | 访问`random.xxxx.top` |

如果博客、图床和随机图片API都部署在同一台服务器上，上述记录值填写同一个公网IP即可。主机记录只填写`img`、`random`等前缀，不填写`https://`或端口。

`@`记录只对应根域名，不会自动覆盖子域名。本文按实际使用的子域名分别添加记录，不需要设置`*`泛解析；如果已经存在适用的泛解析，可以根据现有配置判断是否需要添加独立记录。

后文示例还使用了`www.img.xxxx.top`和`www.random.xxxx.top`。如果需要通过这两个地址访问，还应分别添加主机记录`www.img`和`www.random`，类型为A，记录值填写对应服务器IP，并在对应宝塔站点中绑定这些域名。不使用这些地址时，可以省略，同时从后文的站点绑定和证书申请域名中去掉它们。

保存后可以检查解析结果：

```bash
nslookup img.xxxx.top
nslookup random.xxxx.top
```

结果应包含对应服务器的公网IP。解析存在缓存，修改后可能需要等待原记录的TTL到期。DNS解析完成后，还需要在宝塔中绑定对应域名、配置站点或反向代理，并申请HTTPS证书。

如果后续把图床或博客迁移到OSS/COS，对应主机记录通常改为CNAME，目标填写云服务控制台提供的域名，而不是服务器IP。申请SSL证书时DNS API自动创建的TXT验证记录只用于验证域名所有权，不能代替网站访问所需的A或CNAME记录。

使用中国内地服务器对外提供网站服务时，应先按服务商要求完成备案，具体要求以[阿里云服务器使用说明](https://www.alibabacloud.com/help/en/simple-application-server/product-overview/usage-notes)及备案控制台为准。

### 2.3 安装宝塔与Nginx

从[宝塔官网](https://www.bt.cn/)取得适用于当前系统的安装命令，在服务器上执行。安装完成后记录面板地址、端口和登录信息。

进入宝塔的软件商店安装Nginx。Hexo博客本身不需要PHP和MySQL；如果后面运行PHP随机图API，再为该API单独配置PHP环境。

## 3. 配置本地Hexo环境

这一部分在本地电脑执行。第一次搭建博客按3.1至3.6操作；已有源码仓库时，完成环境安装后直接参考3.7恢复，不要重新初始化项目。

### 3.1 安装 Node.js、Git 与 Hexo

Hexo运行依赖Node.js，npm随Node.js一起安装，Git用于获取主题、备份源码和推送部署文件。

在Ubuntu中安装Git：

```bash
sudo apt update
sudo apt install -y git
```

Node.js从[官网安装页面](https://nodejs.org/en/download)选择适合本机系统的安装方式。版本需要满足Hexo及插件的要求；本项目使用Hexo 7，恢复时可以使用Node.js 22。新建项目应同时核对[Hexo的Node.js版本要求](https://hexo.io/docs/)。

安装完成后确认命令可用：

```bash
node -v
npm -v
git --version
```

安装Hexo命令行工具：

```bash
npm install -g hexo-cli
hexo version
```

全局安装的是`hexo-cli`，具体的Hexo程序和插件由每个博客项目自己的`package.json`管理，不需要再全局安装`hexo`。

如果全局安装提示`EACCES`，优先检查Node.js安装方式和npm目录权限，或使用用户级Node.js版本管理器，不要给整个博客目录设置`777`权限。

### 3.2 首次创建 Hexo 项目

选择存放博客的目录，创建名为`hexo`的新项目：

```bash
hexo init hexo
cd hexo
npm install
```

`hexo init`通常已经安装依赖，后面的`npm install`可以确认依赖齐全。不要在已经有文章和配置的目录中重复执行初始化。[Hexo初始化说明](https://hexo.io/docs/setup)

主要目录结构如下：

```text
hexo/
├── _config.yml          # 站点配置
├── package.json         # Hexo及插件依赖
├── package-lock.json    # 依赖锁文件
├── scaffolds/           # 新建文章、页面使用的模板
├── source/
│   └── _posts/          # Markdown文章
├── themes/              # 主题
└── public/              # 生成后才出现的静态网站目录
```

后续npm和Hexo命令都在博客根目录执行，文章写在`source`中，不要直接修改`public`里的生成结果。

### 3.3 安装 Butterfly 主题

为了方便后续连同主题一起恢复，这里使用Git子模块安装Butterfly。先让新博客目录成为源码仓库，再添加主题：

```bash
git init
git submodule add https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly
npm install --save hexo-renderer-pug hexo-renderer-stylus
```

`hexo-renderer-pug`和`hexo-renderer-stylus`分别负责主题模板和样式的编译，依赖安装方式参考[Butterfly官方仓库](https://github.com/jerryc127/hexo-theme-butterfly)。

使用子模块时，源码仓库记录主题的提交版本；需要备份`.gitmodules`和`themes/butterfly`的子模块记录，恢复时才能取得对应主题。已经存在主题目录或子模块的项目不要重复执行`git submodule add`。

打开站点根目录的`_config.yml`，将主题改成：

```yaml
theme: butterfly
```

首次配置时，将主题默认配置复制到博客根目录：

```bash
cp -n themes/butterfly/_config.yml _config.butterfly.yml
```

`-n`表示目标文件已存在时不覆盖。后续在根目录的`_config.butterfly.yml`中修改主题设置，避免更新主题时覆盖自己的配置。

### 3.4 配置 Hexo 与 Butterfly

这两个配置文件的作用不同：

| 文件 | 主要配置 |
| --- | --- |
| `_config.yml` | 网站标题、作者、语言、域名、文章链接、主题名称和部署方式 |
| `_config.butterfly.yml` | 导航菜单、头像、封面、背景、侧边栏等主题显示效果 |

先修改站点根目录的`_config.yml`，在已有配置项上修改，不要在文件末尾再追加同名字段：

```yaml
title: 我的博客
subtitle: 学习与生活记录
description: 记录技术学习和日常笔记
author: 你的名字
language: zh-CN
timezone: Asia/Shanghai

url: https://xxxx.top
root: /
permalink: :year/:month/:day/:title/

theme: butterfly
```

`url`填写最终对外访问的博客地址。如果使用`blog.xxxx.top`，这里也要对应修改。`root: /`表示网站部署在域名根目录；已有博客不要随意修改`permalink`，否则旧文章链接会变化。

然后编辑`_config.butterfly.yml`中的菜单：

```yaml
menu:
  首页: / || fas fa-home
  时间轴: /archives/ || fas fa-archive
  标签: /tags/ || fas fa-tags
  分类: /categories/ || fas fa-folder-open
  关于: /about/ || fas fa-heart
```

头像可以先使用本地图片。把图片保存为`source/img/avatar.jpg`，设置：

```yaml
avatar:
  img: /img/avatar.jpg
  effect: false
```

Hexo生成时会把这张本地图片复制到`public/img/avatar.jpg`。后续图床搭建完成，也可以将`img`改为对应的HTTPS图片链接。

封面和背景可以先保留默认值，等第6部分图床与随机API配置完成后再修改。YAML使用空格缩进，同一层级需要对齐，冒号后保留空格。

### 3.5 创建分类、标签和关于页面

在博客根目录执行：

```bash
hexo new page categories
hexo new page tags
hexo new page about
```

如果对应页面已经存在，直接编辑，不要重复创建。

将`source/categories/index.md`的Front Matter设置为下面的形式，原有`date`可以保留：

```yaml
---
title: 分类
type: categories
---
```

将`source/tags/index.md`设置为：

```yaml
---
title: 标签
type: tags
---
```

分类和标签页会按文章头部的`categories`和`tags`生成列表。只创建页面不会自动给文章添加分类，需要在文章中填写，例如：

```yaml
---
title: 第一篇博客
categories:
  - 技术文档
  - 博客
tags:
  - Hexo
  - 网站
---
```

这里的分类表示“技术文档 → 博客”的层级，标签则是两个独立的标签。

关于页面`source/about/index.md`是普通页面，直接填写正文即可：

```markdown
---
title: 关于
---

这里记录我的学习笔记、项目实践和生活。

可以在这里补充个人介绍、研究方向和联系方式。
```

时间轴页面由归档生成器生成，不需要执行`hexo new page archives`。菜单配置中的路径要与上面创建的页面目录保持一致。

### 3.6 本地预览

先创建一篇测试文章：

```bash
hexo new "第一篇博客"
```

编辑`source/_posts/第一篇博客.md`，保留文件顶部的Front Matter，在第二个`---`之后书写正文。

生成并启动本地预览：

```bash
hexo clean
hexo generate
hexo server
```

浏览器打开`http://localhost:4000`，检查首页、分类、标签、关于页面和文章页。修改主题配置后，如果预览没有更新，停止服务并重新生成、启动。

终端按`Ctrl+C`停止预览。当前步骤只在本地显示网站，还没有部署到服务器。

如果终端找不到全局`hexo`，在已安装项目依赖的前提下，可以使用本地版本：

```bash
npx hexo generate
npx hexo server
```

### 3.7 已有博客的恢复

换电脑或重新安装系统时，直接恢复源码仓库，不需要再次执行`hexo init`、安装主题或创建页面。

先按3.1安装本地环境，再拉取源码。下面地址需要换成自己的仓库地址：

```bash
git clone --recurse-submodules https://github.com/你的用户名/你的博客仓库.git hexo
cd hexo
npm ci
```

如果之前没有递归克隆，在博客根目录补充执行：

```bash
git submodule update --init --recursive
```

项目中的`.gitmodules`如果使用`git@github.com:...`形式的地址，拉取主题前还需要配置GitHub的SSH访问密钥；主仓库使用HTTPS并不会自动改变子模块的访问方式。

有`package-lock.json`且与`package.json`一致时使用`npm ci`恢复依赖；源码仓库没有锁文件时使用`npm install`。不要只复制`public`目录，它不包含完整文章源码、主题和配置。

确认以下内容已经恢复：

- `source`中的文章、页面和本地图片
- `_config.yml`与`_config.butterfly.yml`
- `themes/butterfly`主题子模块
- `scripts`中的自定义脚本
- `package.json`与`package-lock.json`

最后在本地检查：

```bash
npx hexo clean
npx hexo generate
npx hexo server
```

SSH部署密钥和云服务凭据需要在新电脑单独配置。先确认本地预览正常，再继续下一部分的服务器部署。

## 4. Hexo远程服务器部署

这一节在服务器上执行时，需要使用具有sudo权限的管理账号。

### 4.1 创建Git用户和目录

```bash
sudo apt update
sudo apt install -y git
sudo adduser git

sudo install -d -o git -g git -m 755 /var/repo
sudo install -d -o git -g git -m 755 /var/hexo
sudo -u git git init --bare /var/repo/hexo.git
```

`git`用户只负责接收推送和更新网站目录，不需要加入sudo组，也不需要修改`sudoers`。

### 4.2 配置SSH密钥登录

在本地生成专门用于部署的密钥，已有同名文件时不要覆盖：

```bash
ssh-keygen -t ed25519 -C "hexo-deploy" -f ~/.ssh/hexo_deploy
ssh-copy-id -i ~/.ssh/hexo_deploy.pub git@服务器公网IP
```

如果服务器不允许密码登录，可以通过管理账号在服务器上创建`/home/git/.ssh/authorized_keys`，把本地`hexo_deploy.pub`的内容加入其中，保留已有公钥。

确认服务器上的目录权限：

```bash
sudo chown -R git:git /home/git/.ssh
sudo chmod 700 /home/git/.ssh
sudo chmod 600 /home/git/.ssh/authorized_keys
```

在本地`~/.ssh/config`中加入：

```ssh-config
Host hexo-server
  HostName 服务器公网IP
  User git
  IdentityFile ~/.ssh/hexo_deploy
  IdentitiesOnly yes
```

这里使用固定的服务器IP，避免以后把博客域名解析到COS后，SSH部署也跟着连接到COS。

验证连接：

```bash
ssh hexo-server 'whoami'
```

输出应为`git`。首次连接时核对服务器指纹后再接受。

### 4.3 添加自动部署钩子

在服务器上编辑：

```bash
sudo -u git nano /var/repo/hexo.git/hooks/post-receive
```

写入以下内容：

```bash
#!/bin/bash
set -euo pipefail

while read -r oldrev newrev ref; do
  # 只发布master分支，忽略其他分支和删除分支的操作
  if [ "$ref" != "refs/heads/master" ] || [[ "$newrev" =~ ^0+$ ]]; then
    continue
  fi

  umask 022
  git --git-dir=/var/repo/hexo.git \
      --work-tree=/var/hexo \
      checkout -f "$newrev"

  echo "博客已更新到 $newrev"
done
```

然后设置执行权限：

```bash
sudo chmod 755 /var/repo/hexo.git/hooks/post-receive
```

`/var/hexo`只存放生成结果，不要在其中手动保存文章源码或其他重要文件，后续部署会覆盖受Git管理的文件。

### 4.4. 配置本地一键部署

确认项目已经安装Git部署插件，没有安装时执行：

```bash
npm install --save hexo-deployer-git
```

编辑站点根目录的`_config.yml`，不是`_config.butterfly.yml`：

```yaml
url: https://xxxx.top

deploy:
  type: git
  repo: hexo-server:/var/repo/hexo.git
  branch: master
```

SSH别名`hexo-server`来自上一节的本地SSH配置。部署分支需要和服务器钩子中的`master`保持一致。

首次执行：

```bash
npx hexo clean
npx hexo deploy --generate
```

如果安装了全局Hexo命令，上面的部署命令也就是：

```bash
hexo d -g
```

`-g`负责生成静态页面，`d`调用配置的部署器。Git部署插件及配置格式参考[Hexo一键部署文档](https://hexo.io/docs/one-command-deployment)。

部署结束后，可以从本地检查服务器首页是否存在：

```bash
ssh hexo-server 'ls -l /var/hexo/index.html'
curl -I http://xxxx.top/
```

## 5. 配置Nginx网站

在宝塔的网站管理中添加站点，绑定`xxxx.top`和`www.xxxx.top`，网站根目录设置为`/var/hexo`，不创建数据库。

在站点配置中检查以下核心设置。下面是HTTP阶段的简化示例，已有宝塔配置时修改对应项即可，不要直接覆盖证书及面板维护的其他配置。

```nginx
server {
    listen 80;
    server_name xxxx.top www.xxxx.top;

    root /var/hexo;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

Hexo的文章通常生成在`年/月/日/文章名/index.html`中，`index index.html`让浏览器访问文章目录时能打开对应页面。

在宝塔中检查配置并重载Nginx。第一次部署前，网站目录还是空的，此时不能以能否打开首页判断部署是否成功。

#### 6.1.1 搭建MinIO

进入宝塔面板内，安装Docker，然后在线上镜像中搜索MinIO镜像，然后构建对应容器，并开启`9001-->9001/tcp`和`9000-->9000/tcp`两个端口映射，

### 6.2 随机封面

#### 6.2.1 创建随机图片api

先按2.2节为`random.xxxx.top`添加A记录，指向运行API的服务器公网IP。然后在宝塔面板的网站中添加站点，绑定`random.xxxx.top`，开启PHP，并申请SSL证书；确认HTTPS访问正常后再开启强制HTTPS。

打开这个站点的目录，创建一个`img.txt`和一个`index.php`

在`PicList`的管理中中全部选中并复制图片url，将链接粘贴到img.txt中，作为图片列表的索引

在`index.php`写入如下内容

```php
<?php
//存有美图链接的文件名img.txt
$filename = "img.txt";
if(!file_exists($filename)){
    die('文件不存在');
}
 
//从文本获取链接
$pics = [];
$fs = fopen($filename, "r");
while(!feof($fs)){
    $line=trim(fgets($fs));
    if($line!=''){
        array_push($pics, $line);
    }
}
 
//从数组随机获取链接
$pic = $pics[array_rand($pics)];
header('Cache-Control: no-store, no-cache, must-revalidate, max-age=0');
header('Pragma: no-cache');
header('Expires: 0');
header("Location: $pic");
die();
?>
```

#### 6.2.2 在hexo中使用随机封面

在本地`hexo`根目录下创建`scripts/filters/random_cover.js`文件，内容为

```js
/**
 * Butterfly
 * ramdom cover
 */

'use strict'

hexo.extend.filter.register('before_post_render', function (data) {
  const { config } = this
  if (config.post_asset_folder) {
    const imgTestReg = /\.(png|jpe?g|gif|svg|webp)(\?.*)?$/
    const topImg = data.top_img
    const cover = data.cover
    if (topImg && topImg.indexOf('/') === -1 && imgTestReg.test(topImg)) data.top_img = data.path + topImg
    if (cover && cover.indexOf('/') === -1) data.cover = data.path + cover
  }

  if (data.cover === false) {
    data.randomcover = randomCover()
    return data
  }

  data.cover = data.cover || randomCover()
  return data
},999)// 改成最高优先级，最后执行

function randomCover () {
  const theme = hexo.theme.config
  let cover
  let num

  if (theme.cover && theme.cover.default_cover) {
    if (!Array.isArray(theme.cover.default_cover)) {
      cover = theme.cover.default_cover
    } else {
      num = Math.floor(Math.random() * theme.cover.default_cover.length)
      cover = theme.cover.default_cover[num]
    }
  } else {
    cover = theme.default_top_img || 'data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7'
  }
  if(theme.cover.suffix){
    const randomNum = Date.now().toString(36) + Math.random().toString(36).slice(2)
    if(theme.cover.suffix == 1)
      cover = cover + '?' + randomNum
    else if(theme.cover.suffix == 2)
      cover = cover + '&' + randomNum
  }
  return cover
}

```

打开butterfly主题配置文件`_config.butterfly.yml`：在 cover: 插入suffix: 1 并保存例如：

```yaml
background: https://random.xxxx.top

cover:
  index_enable: true
  aside_enable: true
  archives_enable: true
  suffix: 1
  default_cover:
    - https://random.xxxx.top
```

这里`suffix`目的是在链接后面加入后缀随机数， 0 是不使用后缀；1 是？加随机数；2 是&加随机数

### 7.5 编写脚本实现证书自动更新

`vim ~/auto_ssl.sh`随后写入如下内容

```bash
#!/bin/bash

# 设置环境变量（建议写入 /root/.bashrc 或 .bash_profile 以避免每次都重新 export）
export Ali_Key="LTAI5txxxxxxxxxxxxx"
export Ali_Secret="TJHStNFrxxxxxxxxxxxxxxxxxxx"

# 通用申请函数：重试最多3次
issue_cert() {
  local DOMAIN=$1
  local ALT_DOMAIN=$2
  local RETRY=0
  local SUCCESS=0

  while [ $RETRY -lt 3 ]; do
    echo "尝试申请证书：$DOMAIN ($((RETRY+1))/3)"

    # 捕获输出
    output=$(/root/.acme.sh/acme.sh --issue --dns dns_ali -d "$DOMAIN" -d "$ALT_DOMAIN" 2>&1)

    echo "$output"

    # 检查是否是“未到期跳过续签”
    if grep -q "Skip, Next renewal time" <<< "$output"; then
      echo "证书尚未到期，跳过续签：$DOMAIN"
      return 0
    fi

    # 判断是否成功
    if echo "$output" | grep -q "Your cert is in"; then
      echo "证书申请成功：$DOMAIN"
      SUCCESS=1
      break
    else
      echo "证书申请失败：$DOMAIN，重试中..."
      ((RETRY++))
      sleep 5
    fi
  done

  if [ $SUCCESS -eq 0 ]; then
    echo "证书申请失败（已重试3次）：$DOMAIN"
    return 1
  fi
}

# 安装证书函数
install_cert() {
  local DOMAIN=$1
  local TARGET_DOMAIN=$2

  /root/.acme.sh/acme.sh --install-cert -d "$DOMAIN" \
    --key-file "/www/server/panel/vhost/cert/${TARGET_DOMAIN}/privkey.pem" \
    --fullchain-file "/www/server/panel/vhost/cert/${TARGET_DOMAIN}/fullchain.pem" \
    --reloadcmd "service nginx force-reload"
}

# 所有证书列表
declare -a DOMAINS=(
  "www.random.xxxx.top random.xxxx.top"
  "www.xxxx.top xxxx.top"
  "www.img.xxxx.top img.xxxx.top"
)

# 主程序
for entry in "${DOMAINS[@]}"; do
  DOMAIN1=$(echo "$entry" | awk '{print $1}')
  DOMAIN2=$(echo "$entry" | awk '{print $2}')
  TARGET_DOMAIN=$(echo "$DOMAIN2" | sed 's/^www\.//')

  issue_cert "$DOMAIN1" "$DOMAIN2" && install_cert "$DOMAIN1" "$TARGET_DOMAIN"
done

```

设置可执行权限

```bash
chmod +x ~/auto_ssl.sh
```

添加定时任务（每月1日凌晨 3 点自动执行），编辑 crontab

```bash
crontab -e
```

注释掉acme.h默认续期任务，并添加这一行

```bash
0 3 1 * * /root/auto_ssl.sh >> /var/log/auto_ssl.log 2>&1
```

## 9. 常见问题

| 现象 | 排查方向 |
| --- | --- |
| SSH连接超时 | 公网IP、SSH端口、云防火墙及系统防火墙 |
| Git推送提示Permission denied | SSH用户名、密钥、公钥文件权限以及仓库所有者 |
| 推送成功但网页未更新 | 钩子是否有执行权限，推送分支是否为master，钩子执行是否报错 |
| 网站返回403 | 根目录是否正确、是否有index.html、Nginx是否能读取文件及遍历目录 |
| 首页正常但文章404 | 文章对应目录是否生成，Nginx是否配置index.html |
| 证书续期成功但浏览器仍提示过期 | Nginx读取的证书路径、install-cert和reloadcmd是否正确 |
| 所有封面都是同一张图 | 图片URL是否完全相同，随机API及中间缓存是否正常 |

后续如果把博客迁移到COS，变化的是上传方式和域名解析。本地Hexo生成流程可以保留，但服务器上的PHP随机图API等动态服务需要另行处理，不能把PHP源码上传到对象存储就当作服务运行。
